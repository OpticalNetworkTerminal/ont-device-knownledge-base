## 总览

华为 ONT 的公开资料主要来自四类来源：

- 官方产品与维护资料，能确认产品线、管理协议、标准术语与部分维护能力。
- GPL、Bootlog、拆机与固件分析，能补全 Linux、Bootloader、文件系统和配置处理细节。
- 恩山、ChinaDSL、52pojie、OpenWrt Forum 等社区资料，覆盖大量运营商定制机的实际经验。
- GitHub 与个人博客，常提供串口日志、配置样例、AES 工具、脚本名和恢复方法。

这意味着华为光猫知识库天然是“官方资料 + 社区经验 + 逆向资料”的混合体。对于社区高频且多源一致的信息，本页直接整理为正式条目；对于仍有争议的内容，放到文末的 `待验证`。

## 典型进入路径

### Web 管理页

Web 是最普遍的管理入口，但也是最常被运营商阉割的入口。社区资料中最常见的限制包括：

- 只开放普通用户，不开放超管。
- 隐藏桥接、VLAN、TR069、WAN 详情、SN/MAC 等页面。
- 在恢复出厂后仍保留定制模板。
- 通过 TR069 或启动脚本重新覆盖本地修改。

常见思路不是直接“爆破页面”，而是通过导出配置、恢复默认模板、切换地区模板、启用 Telnet 或改用串口进入更底层的维护环境。

### Telnet

Telnet 是社区资料中最常见的实际维护入口，常见场景包括：

- 直接进入 `WAP>` 维护命令环境。
- 使用 `su` 切换权限。
- 使用 `shell` 进入更底层的 `Dopra Linux` Shell。
- 借助 `tftp`、`gzip`、`aescrypt2` 修改 `hw_ctree.xml`。

社区中常见的管理地址包括 `192.168.1.1` 与 `192.168.100.1`。常见账号也会随运营商与固件变化，包括 `root/admin`、`root/adminHW`、`telecomadmin` 等。这里不把任何单个账号当成最终结论，而是只记录它们在公开资料中高频出现。

### SSH / STelnet

官方资料能证明华为设备体系存在 `Telnet/STelnet` 管理概念，但民用 EchoLife 固件是否默认开放 `SSH/STelnet`，目前没有像 Telnet 那样稳定、多型号一致的社区证据。

因此当前可作为正式结论的只有两点：

- 华为官方管理体系中存在 `STelnet` 概念。
- 在民用光猫资料中，`SSH/STelnet` 的可用性明显弱于 `Telnet` 与 `Serial`。

### Serial / UART / TTL

当 Web 和 Telnet 都不可用时，串口是最稳定的底层入口之一。研究资料中最完整的案例来自 `HG8012H`：

- 板上存在 UART/TTL 焊点。
- 启动日志显示串口速率为 `115200`。
- 能看到 `U-Boot 2010.03`、Linux 版本、分区表和文件系统信息。

串口的重要性不只在“登录 Shell”，更在于它是确认 Bootloader、Kernel、分区布局、文件系统和恢复路径的最强证据来源之一。

## 配置文件与权限体系

### `hw_ctree.xml`

`hw_ctree.xml` 是当前资料池中最常见的华为运行配置文件名。社区常用它做以下事情：

- 读取或恢复超级管理员。
- 修改用户权限级别。
- 调整连接数或 Wi-Fi 限制。
- 关闭或修改 TR069 参数。
- 恢复桥接或查看运营商模板差异。

在很多社区案例里，实际工作流不是直接编辑设备数据库，而是：

1. 导出 `hw_ctree.xml`
2. 解密或解压
3. 修改 XML 节点
4. 重新压缩/加密
5. 回传设备并重启

### `hw_default_ctree.xml`

`hw_default_ctree.xml` 常被当作“默认值参照物”。它的价值主要在于：

- 对比当前运行配置与出厂模板的差异
- 判断运营商是通过模板还是运行时下发覆盖配置
- 恢复某些被隐藏或被锁定的页面行为

### `hw_boardinfo`

社区资料中，`hw_boardinfo` 经常和以下主题一起出现：

- `SN`
- `MAC`
- 模式切换
- 地区/定制识别

现阶段可以确认它是一个高价值的板级/设备标识对象，但不同型号里具体字段作用差异较大，不适合在主文中直接把某个字段说明写死。

### 超级管理员

围绕超管的公开资料大致分成三类：

- 账号线索：如 `telecomadmin`、`root`、`admin`、`getaccess`
- 权限线索：如 `UserLevel="0"`
- 密码存储线索：如 `PassMode="2"`、`SHA256(MD5(password))`

多来源一致的部分是：

- 华为配置文件中确实存在用户节点与权限级别概念。
- 社区资料普遍将 `UserLevel="0"` 视为高权限级别。
- `telecomadmin` 是中国区定制机最常见的超管线索之一。

需要避免过度简化的部分是：

- 不同地区与运营商的密码方案不同。
- 有的固件允许直接改配置恢复高权限，有的会被 TR069 或模板回写。
- `root/admin` 在部分机型或恢复场景可用，不代表全系列通用。

## 配置加解密

### `aescrypt2`

这是目前公开资料中最稳定、最常见的华为配置处理工具线索。围绕它可以形成较清晰的结论：

- `aescrypt2` 经常用于处理华为配置文件。
- 社区资料普遍将 `1` 视为解密模式，将 `0` 视为加密模式。
- `AESCrypt2` 项目为 `HG8245` 类资料提供了较清晰的 key 与处理流程旁证。

研究资料中还出现了以下线索：

- 配置文件可能带有额外 `8-byte header`
- 设备侧可能存在 `/etc/wap/aes_string`
- 某些配置文件先加密，再配合 `gzip`

### `descrypt`

`descrypt` 已在多个社区搜索入口中出现，但目前缺乏足够稳定的多源上下文，因此它在正式知识库中保留为“已出现但未澄清”的对象，而不作为成熟工具下结论。

## 运营商限制

华为光猫资料里最常见的问题并不是“设备不支持”，而是“设备被运营商定制后不开放”。常见限制包括：

- Web 页面删减
- 账号权限降级
- 桥接与 VLAN 页面隐藏
- 地区模板锁定
- 启动脚本恢复运营商配置
- TR069 再次回写

这也是为什么华为光猫的公开资料里，会反复出现下面这些对象：

- `customizepara.txt` / `customizepara.xml`
- `choose*.xml`
- `hw_default_ctree.xml`
- `Equip.sh`
- `restorehwmode.sh`

这些对象不一定在所有机型上都出现，但它们共同反映了一个规律：华为 ONT 的“原厂能力”和“运营商放出的能力”经常不是同一回事。

## TR069 与 OMCI

### TR069

TR069 是社区最常提到的远程覆盖来源之一。它常被关联到以下问题：

- 修改后配置被恢复
- 超管密码被重写
- 路由/桥接模式被改回
- ACS 远程管理重新接管

当前更稳妥的整理方式不是“TR069 一定会覆盖所有修改”，而是：

- 在大量社区案例中，TR069 是最常见的远程回写解释。
- 如果某次配置修改重启后失效，应首先考虑 TR069 或运营商模板回写。

### OMCI

OMCI 更偏向 ONT 与 OLT 的管控链路。社区对它的讨论通常集中在：

- 换设备后能否正常注册
- 双模或跨运营商场景的兼容性
- 厂商私有 ME 是否导致功能缺失

因此，`OMCI` 在正式知识库里更适合被理解为“兼容性背景变量”，而不是单个可以靠 Web 页面直接开关的功能项。

## 身份参数：SN、MAC、LOID

这部分是社区高频主题，但不同地区差异非常大。

### SN

`SN` 常见于：

- 用第三方 ONT 替代原装光猫
- 在同品牌不同机型之间迁移注册参数
- 判断 OLT 是否按序列号放行

现有资料可以支持的表述是：华为光猫与替代设备资料中，`SN` 是最核心的注册参数之一。

### MAC

`MAC` 常与以下情况一起出现：

- 运营商模板识别
- 局域网或管理侧限制
- 某些恢复原厂/恢复模板场景

但它是否直接影响 PON 注册，要按具体机型与运营商区分。

### LOID

`LOID` 在中国区资料中很常见，特别是高版本机型与运营商注册问题：

- 注册进度异常
- `ITMS` 或认证失败
- 换机后无法通过认证

现阶段适合把它列为“高频注册参数”，而不是统一写成“所有华为 ONT 都必须改 LOID”。

## 升级、恢复与模式切换

### 升级

社区资料里，升级入口常分成三类：

- Web 导入升级包
- 通过 `load pack by tftp` 导入升级包或补全包
- 通过 Shell 侧文件回传和脚本恢复

当前最重要的不是死记某个包名，而是先分清：

- 这是完整固件包，还是补全包
- 这是运营商包，还是原厂包
- 导入后只会升级版本，还是会切换模板/模式

### 恢复

恢复主题在华为资料中主要有三种含义：

- 恢复默认配置
- 恢复华为原厂界面/模式
- 恢复运营商定制状态

社区里提到的 `restorehwmode.sh`、`choose*.xml`、`customizepara.*` 都应放在这个上下文里理解，而不是孤立看成某一个万能脚本。

### 双模

社区提到的“双模”通常指：

- GPON/EPON 双模
- 某些兼容补丁或跨 OLT 适配思路

这部分公开资料较多来自社区经验，正式文档里只保留“常见讨论主题”和机型线索，不对实际支持矩阵做过度下结论。

## LED、Mesh 与 Wi-Fi

### LED

LED 在社区资料里常被当作状态侧写，而不是独立功能点。例如：

- 升级时灯态变化
- 光口注册状态
- 恢复后是否重新进入运营商模板

因此 LED 更适合和“恢复/升级/注册状态”放在一起理解。

### Mesh

`Mesh` 与 `EasyMesh` 主要出现在较新的 Wi-Fi 一体机资料中，如 `HN8145X6` 一类高版本设备。现有资料表明：

- 社区确实把它当成高版本机型的重要功能点
- 但比起超管、TR069、SN/LOID，这部分公开深度明显不足

当前可先视作“高版本特性线索”保留。

## 待验证

以下内容已经进入正式知识库，但目前仍存在明显争议或证据不足：

- `descrypt` 的真实命令名、参数和适用固件
- 民用 EchoLife 固件中的 `SSH/STelnet` 默认可用性
- `SN`、`MAC`、`LOID` 在不同运营商定制固件中的字段映射
- `restorehwmode.sh` 的适用机型与真实行为
- `Equip.sh` 是否为某些高版本机型通用的 root 开关
- `Mesh`、`双模`、`LED` 相关功能在不同机型上的实际支持范围
