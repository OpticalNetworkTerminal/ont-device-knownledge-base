# 最佳实践

## 读取优先

DBus 文档和工具开发应先做只读能力：

1. `ListNames`
2. `Introspect`
3. `GetManagedObjects`
4. `GetAll`

在没有回滚方案前，不要自动调用 `Set`、`SetValues`、`DeleteObject`、`RemoveAllObjects`、`Reboot`、`Restore`、`Upgrade`。

## 保存现场

修改前至少保存：

- 目标 object 的 introspection 输出。
- `GetAll` 当前值。
- 相关父集合的 `GetManagedObjects`。
- Web 后台页面当前状态截图或字段值记录。

## 字段判断

不要因为对象暴露 `Set` 就认为所有字段可改。可修改性以 property 权限为准：

- `readwrite`：候选可修改。
- `readonly`：只读状态，不建议强行 Set。

## 按功能域隔离测试

推荐顺序：

1. 客户端别名：`LANHosts.DevName`
2. LED：`Peripheral/LED.LEDStatus`
3. WiFi 非关键开关：SSID 广播、自动信道
4. WiFi 密码、DHCP 地址池、HTTP 密码
5. 防火墙、QoS、WAN、系统命令

越靠后风险越高。

## Web 后台映射验证

推测某页面对应某对象后，应通过以下方式验证：

- 打开页面前后抓 DBus monitor。
- 修改页面字段后观察 `Set/SetValues`。
- 对比提交前后的 `GetAll`。
- 查找 Web 进程或后端 CGI 是否调用 `gdbus/dbus-send/libdbus`。

## 自动化建议

自动化脚本应实现：

- 白名单对象。
- 白名单属性。
- 修改前备份。
- 修改后验证。
- 超时和错误恢复。
- 默认只读模式。

## 命名建议

知识库中统一使用短路径：

```text
Config/WLAN/Devices/1
```

完整调用时再补全：

```text
/com/cuc/igd1/Config/WLAN/Devices/1
```
