# 软件架构

B/C

## 当前结论

公开资料可确认 ZTE ONT 常见的软件管理面由 Web 管理界面、配置数据库、导出配置文件和维护命令组成，但不同型号和运营商版本差异明显。

## 已验证内容

- GitHub 社区工具长期围绕 `config.bin`、`db_user_cfg.xml`、`db_default_auto_cfg.xml` 等文件工作，说明配置导出/导入与 XML/二进制封装是 ZTE 设备的重要配置形态。
- 多个社区来源可交叉验证 `sendcmd 1 DB ...` 与 `sidbg 1 DB ...` 被用于查询和修改运行配置数据库。
- 社区命令样本反复出现 `TelnetCfg`、`DevAuthInfo`、`MgtServer`、`WANC` 等表名，说明这些对象至少在部分机型/固件中稳定存在。
- 在部分较新的运营商定制固件中，还存在独立于 `sendcmd` 的插件管理框架：启动层有 `appmgr`，接口层有 `com.ctc.appframework1.AppAgent`，可列出、查询、停止和启动插件。

## 插件框架

公开资料显示，部分 ZTE 光猫不是只有“Web + 配置数据库”两层，还带有独立的运营商插件体系。

### 当前已知组成

- 启动脚本：`/etc/init.d/appmgr`
- 管理接口：`com.ctc.appframework1`
- 对象路径：`/com/ctc/appframework1`
- 典型接口：`com.ctc.appframework1.AppAgent`
- 典型方法：`List`、`GetStatus`、`Stop`、`Run`

### 当前理解

- `appmgr` 负责插件管理服务启动
- 插件常与远程运维、配置下发、日志上报、升级、游戏加速等运营商扩展功能相关
- 在纯桥接场景下，社区通常倾向于停掉这类插件
- 在光猫继续承担拨号和 IPv6 家庭网关职责时，禁用全部插件可能带来副作用

## 社区资料

- `sendcmd`/`sidbg` 背后是否直接对应 D-Bus、私有 IPC，还是中间再封装一层，目前公开证据不足。
