# 外部工具对照

本文记录与本项目相关的公开工具，并说明它们和当前 G7615 分析结论的对应关系。

## yuleniwo/zxcfg

项目地址：`https://github.com/yuleniwo/zxcfg`

`zxcfg` 支持面较完整，覆盖：

- 早期 `ctce8_*.cfg` 管理台备份格式。
- `db_default_cfg.xml` / `db_user_cfg.xml` 类加密配置数据库。
- hardcodefile 解密。
- `paramtag` 参与 user DB key 派生。
- cfg 打包、XML 容器打包、压缩、加密。

与当前 G7615 样本已验证结论一致的点：

| 项目 | `zxcfg` 逻辑 | 当前样本验证 |
|---|---|---|
| 默认 DB key | `PON_Dkey` | 一致 |
| 默认 DB IV | `PON_DIV` | 一致 |
| user fallback key | `8cc72b05705d5c46f412af8cbed55aad` | 来源一致，但当前样本未用它解开 user DB |
| user IV | `667b02a85c61c786def4521b060265e8` | 来源一致，有效字符串为前 31 字符 |
| user 个性化 tag | `ID_INDIVKEY = 1824`，即 `0x0720` | 一致 |
| user key 方法 | `MD5(seed, 33)` 后转 hex，再 `SHA256(hex[0:31])` | 一致 |
| IV 方法 | `SHA256(iv_string[0:31])` 取前 16 字节 | 一致 |
| 默认 key 方法 | `SHA256(key_string[0:31])` | 一致 |

`zxcfg` 的关键代码逻辑可概括为：

```text
paramtag tag 0x0720
  -> 32 字节 seed
  -> MD5(seed + NUL, 33)
  -> hex string
  -> SHA256(hex[0:31])
  -> AES-256 key

CSP_USER_AESCBCENCRY_IV
  -> iv_string[0:31]
  -> SHA256
  -> first 16 bytes
  -> AES-CBC IV
```

注意事项：

- `zxcfg` 说明算法和字段 ID 是通用逻辑，但不能证明不同机器的
  `tag 0x0720` 值固定。
- 当前 G7615 样本实际使用 `tag 0x0720` 派生 key；fallback user key
  未命中样本 user/backup DB。
- 跨机器恢复是否可行，仍要比较两台机器的 `tag 0x0720` seed 和最终
  `user_key_string`。

## TommyLau/ztecfg

项目地址：`https://github.com/TommyLau/ztecfg`

`ztecfg` 主要面向较早的管理台备份格式：

```text
ctce8_*.cfg
  -> USB cfg header
  -> zlib block
  -> 明文 XML
```

它不覆盖当前 G7615 `db_user_cfg.xml` 的 AES/zlib 双层容器，也不包含
`paramtag` 派生 user key 的逻辑。

与当前 G7615 的差异：

| 项目 | TommyLau/ztecfg | 当前 G7615 |
|---|---|---|
| AES | 无 | 有 |
| key/iv 派生 | 无 | hardcodefile + paramtag |
| `paramtag 0x0720` | 无 | user DB key seed |
| U 盘备份内嵌内容 | 直接 zlib XML blocks | 内嵌完整 `db_user_cfg.xml` 容器 |

因此，`ztecfg` 可作为早期格式参考，但不能用于证明当前 G7615 的
`tagparam` 固定或不固定。
