# 权限模型

## 简介

本文说明 Linux 经典权限模型的作用，以及为什么用户、组、读写执行位仍然是系统运行的基础边界。

## 背景

很多现代安全机制都建立在更复杂抽象上，但 Linux 运行时最基础的安全边界，仍然是 UID、GID 和文件权限位。

## 基本概念

UID 是用户身份，GID 是组身份，`rwx` 是读写执行权限。

## 工作原理

进程访问文件、socket、设备节点等对象时，内核会结合对象元数据与进程身份判断是否允许。

## 设计目的

提供最基本的访问控制，把资源访问与身份关联起来。

## 优缺点

优点：简单、通用。

缺点：表达能力有限。

## 典型应用

- shell 用户权限
- daemon 专用用户
- Unix socket 访问控制

## 在 Buildroot 中的位置

Buildroot 设备虽常只有少量用户，但权限模型仍决定哪些服务能读配置、写日志、绑定 socket、访问设备。

## 在 OpenWrt 中的位置

OpenWrt 也依赖传统权限模型保护配置、运行时 socket 和脚本执行入口。

## 在光猫中的体现

光猫上即使只有少量用户或默认 root 模式，权限模型仍影响 Web/CLI 对底层资源的访问边界。

## 实际案例

为什么某个 socket 文件存在但程序连不上？除了服务没监听，还可能是文件权限不允许当前身份访问。

## 实践操作

```bash
id
ls -l /etc | head -n 20
ls -l /var/run 2>/dev/null | head -n 20
```

怎么看：看当前 UID/GID、对象权限和拥有者。
