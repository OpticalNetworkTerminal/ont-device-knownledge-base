# 日志系统

## 简介

本文说明 Linux 运行时中的日志来源，以及为什么内核日志、daemon 日志、控制台输出和持久化日志常常不是一回事。

## 背景

排查系统问题时，很多人只找一个 log 文件。但 Linux 的日志来源通常分散在内核 ring buffer、daemon 输出、syslog 和临时目录里。

## 基本概念

日志系统通常至少包含内核日志、用户态服务日志和收集与转发组件。

## 工作原理

不同来源的日志走不同链路：内核到 ring buffer，用户态进程写 stdout/stderr 或 syslog socket，日志守护进程再输出到文件、内存或远端。

## 设计目的

提供故障排查依据，保留运行时行为痕迹。

## 优缺点

优点：可观测性强。

缺点：嵌入式系统常受空间限制，日志可能重启即失。

## 典型应用

- `dmesg`
- syslog
- daemon 自己的日志文件

## 在 Buildroot 中的位置

Buildroot 系统常用轻量日志方案，尤其在只读 Rootfs 上会把部分日志放到 tmpfs 或 ring buffer。

## 在 OpenWrt 中的位置

OpenWrt 同样强调轻量日志，在有限空间内平衡调试能力和资源消耗。

## 在光猫中的体现

光猫的很多日志可能位于 ring buffer、`/tmp`、运行时目录或专用管理日志机制中，而不一定长期持久化。

## 实际案例

为什么问题 reboot 后日志全没了？因为日志可能只存在 tmpfs、内存 ring buffer 或易失性运行时目录。

## 实践操作

```bash
dmesg | tail -n 50
ls /var/log 2>/dev/null | head -n 30
find /tmp -maxdepth 2 -type f 2>/dev/null | head -n 30
```

怎么看：区分内核日志、传统日志目录和运行时临时日志。
