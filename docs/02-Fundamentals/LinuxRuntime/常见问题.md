# 常见问题

## 简介

本文汇总 Linux 系统运行机制中最常见的误解和排查入口。

## 背景

这部分知识最怕“每个概念都知道一点，但一到现场就串不起来”。FAQ 的目标就是把最常见问题落回统一判断路径。

## 基本概念

典型问题包括：

- 为什么 `ps` 是这样
- 为什么 `/proc` 没有真实文件
- 为什么 `/sys` 写值会改行为
- 为什么 mount 后目录内容变化
- 为什么 socket 也是文件
- 为什么容器里还有 `/proc`、`/sys`、`/dev`

## 工作原理

统一排查顺序通常是：

1. 先确认 PID 1 和进程树
2. 再看挂载
3. 再看 `/proc`、`/sys`、`/dev`
4. 再看 socket 与权限
5. 最后看 namespace / cgroup / 容器视图

## 在 Buildroot 中的位置

Buildroot 设备的很多现象，例如 BusyBox init、tmpfs、轻量 `/dev` 和早期 `/proc` 挂载，都可用本 FAQ 快速定位。

## 在 OpenWrt 中的位置

OpenWrt 的 `procd`、`ubus`、运行时挂载和本地 socket，也都能映射到这些问题上。

## 在光猫中的体现

光猫现场最常见的问题就是把 Linux 伪文件系统、运行时挂载和本地 IPC 误当普通文件或普通目录。

## 实际案例

### 为什么 `/proc` 没有真正文件

因为它是内核按需生成的伪文件系统接口。

### 为什么 `/sys` 可以修改驱动

因为写入动作会进入内核属性处理逻辑，不是在改磁盘文本。

### 为什么 socket 也是文件

因为 Linux 通过 VFS 和文件描述符模型统一管理 I/O 对象，Unix socket 还能落到路径上。

### 为什么容器里还有 `/proc`、`/sys`、`/dev`

因为容器共享同一内核，只是通过 namespace 和挂载视图看到自己的 API 文件系统实例。

## 实践操作

```bash
ps -ef
mount
ls /proc | head
ls /sys | head
ls /dev | head
find / -type s 2>/dev/null | head
```

怎么看：

- 把进程、挂载、伪文件系统、设备节点、socket 放在同一张运行时地图里看
