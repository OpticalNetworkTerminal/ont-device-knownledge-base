# 线程

## 简介

本文说明线程与进程的关系，以及为什么 Linux 里很多多线程程序在外部看上去仍像一个进程。

## 背景

应用开发者更熟悉语言级线程，但在运行时分析里，关键是理解线程与进程共享了什么、隔离了什么。

## 基本概念

- 进程更强调资源边界
- 线程更强调共享地址空间下的并发执行

## 工作原理

Linux 线程共享同一进程的大部分资源，例如地址空间和打开文件，但仍作为独立任务被调度。

## 设计目的

在线程共享数据的前提下实现并发执行，减少多进程通信成本。

## 优缺点

优点：

- 共享数据方便
- 并发成本通常低于多进程

缺点：

- 互相影响更强
- 调试复杂度更高

## 典型应用

- Web 服务线程池
- 日志线程
- 事件循环和工作线程组合

## 在 Buildroot 中的位置

Buildroot 选择的 libc 和线程库能力，会直接影响目标系统的线程支持方式。

## 在 OpenWrt 中的位置

OpenWrt 上很多服务更偏事件驱动，但多线程程序同样常见。

## 在光猫中的体现

光猫里的 Web 服务、网络管理进程和后台处理程序，可能内部是多线程，但外部只看到一个主进程名。

## 实际案例

为什么 `ps` 里看起来只有一个服务，但 CPU 占用像有多路工作？因为它可能在同一进程内开了多个线程。

## 实践操作

```bash
ps -T -p 1
ls /proc/self/task
cat /proc/self/status
```

怎么看：

- `ps -T`：看线程
- `/proc/<pid>/task`：看线程级任务视图
