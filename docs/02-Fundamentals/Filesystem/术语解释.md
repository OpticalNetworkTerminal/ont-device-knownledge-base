# 术语解释

## 简介

本篇用于汇总 Filesystem 章节内高频术语，并与全局术语表保持一致。遇到术语歧义时，以 [Glossary](../../Glossary.md) 为全局基准，本篇聚焦文件系统与固件分析语境中的用法。

## Rootfs

Root Filesystem，系统启动后挂载到 `/` 的根文件系统。它可以来自 SquashFS、UBIFS、Ext4、initramfs 等不同形式。

关联章节：

- [Rootfs](./Rootfs.md)

## Rootfs Image

Rootfs 的镜像文件形式，是构建、封装、刷写、升级时常见的交付形态。Rootfs Image 不一定等于最终 Firmware。

## Firmware

设备使用的固件交付物，通常包含 Kernel、Rootfs 以及校验、封装头、设备匹配信息等。Firmware 通常高于单独文件系统镜像这一层级。

关联章节：

- [Firmware 文件结构](./Firmware文件结构.md)

## Factory Firmware

面向首次刷写、恢复、量产或系统迁移的固件形式，通常更强调完整写入和初始化能力。

关联章节：

- [Factory Firmware](./FactoryFirmware.md)

## Upgrade Firmware

面向在线升级或已有系统内升级的固件形式，通常更强调保留配置、降低风险与适配当前升级入口。

关联章节：

- [Upgrade Firmware](./UpgradeFirmware.md)

## VFS

Virtual Filesystem，Linux 内核中的虚拟文件系统层，为不同文件系统提供统一接口。

关联章节：

- [VFS 虚拟文件系统](./VFS虚拟文件系统.md)

## Mount

把一个文件系统实例接入目录树的过程。挂载后，目录路径才会映射到具体设备、镜像或内核伪文件系统。

关联章节：

- [Mount 机制](./Mount机制.md)

## Mount Namespace

Linux Namespace 的一种，使不同进程组拥有彼此隔离的挂载视图。

关联章节：

- [Mount Namespace](./Mount Namespace.md)

## Pivot Root

把当前根文件系统切换为另一个挂载点的内核机制，常用于启动阶段从临时根切换到真正 Rootfs。

关联章节：

- [PivotRoot](./PivotRoot.md)

## Chroot

为进程改变其“看到的根目录”的机制，常用于调试、构建与隔离，但不等同于真正切换系统根。

关联章节：

- [Chroot](./Chroot.md)

## Device Node

`/dev` 下表示设备访问入口的特殊文件，用于把用户空间操作映射到内核设备接口。

关联章节：

- [Device Node](./Device Node.md)
- [BlockDevice 与 CharacterDevice](./BlockDevice与CharacterDevice.md)

## proc / procfs

由内核提供的伪文件系统，用于暴露进程、内核状态和系统运行信息。

关联章节：

- [proc](./proc.md)

## sysfs

用于导出内核对象模型与设备树状信息的伪文件系统，常挂载在 `/sys`。

关联章节：

- [sysfs](./sysfs.md)

## devtmpfs

由内核自动维护基础设备节点的文件系统，常挂载在 `/dev`，并与 `mdev`、`udev` 等机制协同工作。

关联章节：

- [devtmpfs](./devtmpfs.md)

## tmpfs

基于内存的临时文件系统，可使用交换空间，适合临时目录与运行时文件。

关联章节：

- [tmpfs](./tmpfs.md)

## ramfs

更简单的内存文件系统，没有大小限制控制机制，通常不如 tmpfs 常用。

关联章节：

- [ramfs](./ramfs.md)

## Overlay

把只读下层和可写上层叠加成统一目录视图的机制，是很多嵌入式系统保存配置的关键设计。

关联章节：

- [Overlay 机制](./Overlay机制.md)
- [OverlayFS](./OverlayFS.md)

## SquashFS

只读压缩文件系统，常用于嵌入式设备的 Rootfs。

关联章节：

- [SquashFS](./SquashFS.md)

## JFFS2

面向原始 Flash 的日志结构文件系统，适用于较早期或特定资源约束场景。

关联章节：

- [JFFS2](./JFFS2.md)

## MTD

Memory Technology Device，Linux 对原始 Flash 设备的抽象层，不同于块设备接口。

关联章节：

- [MTD](./MTD.md)

## UBI

Unsorted Block Images，位于 MTD 之上的管理层，用于坏块处理、磨损均衡和卷管理。

关联章节：

- [UBI](./UBI.md)

## UBIFS

运行在 UBI 之上的文件系统，适用于原始 NAND Flash 场景。

关联章节：

- [UBIFS](./UBIFS.md)

## Ext4

运行在块设备上的通用 Linux 文件系统，常用于 eMMC、SSD、SATA、SD 卡等介质。

关联章节：

- [Ext2 Ext3 Ext4](./Ext2_Ext3_Ext4.md)

## F2FS

Flash-Friendly File System，面向块设备型 Flash 介质优化的文件系统，常见于 eMMC、UFS、SSD 场景。

关联章节：

- [F2FS](./F2FS.md)

## Loop Device

把普通文件映射为块设备接口的机制，常用于挂载镜像文件、测试文件系统与分析 Rootfs Image。

关联章节：

- [LoopDevice](./LoopDevice.md)

## Overlay Upperdir

Overlay 的上层可写目录，运行时新增、修改、删除的信息最终记录在这里，而不是写入只读 lowerdir。

## Whiteout

Overlay 或联合挂载实现中用于表达“下层文件在合并视图中应被隐藏”的标记机制。

## Wear Leveling

磨损均衡，目的是让 Flash 的擦写负载更均匀分布，延长寿命。UBI 在原始 Flash 场景中承担这一重要职责。

## PEB / LEB

在 UBI / UBIFS 语境中：

- PEB：Physical Erase Block，物理擦除块
- LEB：Logical Erase Block，逻辑擦除块

UBI 负责把物理层映射为逻辑层，供上层文件系统使用。

## 实践操作

### 1. 用 `cat /proc/filesystems` 对照术语

```bash
cat /proc/filesystems
```

作用：

- 查看系统支持的文件系统类型

怎么看：

- 输出中出现的 `squashfs`、`ubifs`、`tmpfs`、`overlay` 等名词，可以和本篇术语逐一对应

### 2. 用 `findmnt` 理解术语在系统中的落点

```bash
findmnt
```

作用：

- 查看术语不是停留在概念层，而是如何出现在真实挂载树中

怎么看：

- 可以直观看到 `/`、`/proc`、`/sys`、`/dev`、`/tmp` 分别对应什么文件系统
