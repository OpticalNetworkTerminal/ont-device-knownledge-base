# 术语解释

## 简介

本文整理 Buildroot 学习中最常见的术语，帮助后续文档保持一致表达。

## 背景

嵌入式 Linux 文档常把“构建系统、包、镜像、根文件系统、BSP、工具链、sysroot”等概念混写。术语不清，后续理解会持续跑偏。

## 原理

术语表的目标不是面面俱到，而是先把 Buildroot 语境里最常见的词固定下来。

## 组成

| 术语 | 含义 |
| --- | --- |
| Buildroot | 面向嵌入式 Linux 的构建系统 |
| defconfig | 去掉默认值后的精简配置文件 |
| `.config` | 当前完整构建配置 |
| Toolchain | 交叉编译工具链 |
| Sysroot | 目标头文件和库组成的开发根 |
| Skeleton | 目标根文件系统的初始骨架 |
| Overlay | 在构建后覆盖到目标文件树的静态文件树 |
| Post-build | 在镜像生成前执行的后处理脚本 |
| Rootfs | 根文件系统 |
| BusyBox | 可裁剪多调用二进制工具集 |
| DeviceTree / DT | 描述硬件的树形数据结构 |
| DTB | 编译后的设备树二进制 |
| BSP | 板级支持包 |
| Factory Firmware | 用于工厂刷机的固件格式 |
| Upgrade Firmware | 用于在线或维护升级的固件格式 |
| br2-external | Buildroot 外部扩展树 |

## 工作流程

阅读 Buildroot 文档时可以按这个顺序理解：

1. `defconfig` 决定系统选择
2. Toolchain 决定怎么交叉编译
3. Package 决定编哪些组件
4. Rootfs / Overlay 决定目标文件树
5. Image / Firmware 决定最终交付产物

## 实际应用

术语统一后，团队沟通会更高效。例如：

- “改 rootfs”应区分是改 overlay，还是改包安装内容
- “改固件”应区分是改 rootfs 镜像，还是改产品封装头
- “改系统配置”应区分是改 Buildroot `.config`，还是改 BusyBox / Kernel 配置

## 光猫中的体现

在光猫项目里，术语混淆最常见于：

- 把 BSP 和 Buildroot 混为一体
- 把 rootfs 与最终固件混为一体
- 把设备树和板级脚本混为一体

统一术语后，问题定位会快很多。

## 注意事项

- 术语表是通用定义，具体项目可能有私有命名。
- 私有命名不应覆盖通用概念本身。
- 后续新文档若引入专有术语，应优先补入本表。
