# 常见问题

## 简介

本文汇总 Buildroot 学习和工程实践中的常见问题，重点帮助读者建立正确边界感。

## 背景

Buildroot 的难点往往不在“会不会点 menuconfig”，而在于是否理解它的定位。如果定位错了，后续很多操作都会变成反模式。

## 原理

以下问题最常见：

- Buildroot 是不是发行版
- `output/target/` 能不能直接刷机
- 为什么目标机没有开发文件
- 为什么不在目标机上用包管理器
- overlay 与 post-build 到底怎么选

## 组成

### Buildroot 是发行版吗

不是。它更准确地说是“嵌入式 Linux 构建系统”。

### `output/target/` 能直接当根文件系统用吗

通常不应直接用。官方手册明确说明它缺少设备节点且权限不完整，最终应使用 `output/images/` 里的镜像。

### 为什么目标机没有编译器和开发头文件

因为 Buildroot 默认面向运行期系统，不是面向目标机本地开发环境。开发文件通常位于工具链 sysroot 中。

### 为什么不生成 `.deb` 或 `.ipk`

因为 Buildroot 的重点不是在线包管理，而是整体镜像构建。

### overlay 和 post-build 怎么选

- 静态文件覆盖：优先 overlay
- 脚本修整：post-build
- 基础骨架重做：custom skeleton

## 工作流程

排查思路建议：

1. 先确认问题属于工具链、包、Kernel、Rootfs 还是镜像封装
2. 再看是源码树配置问题还是 `output/` 产物问题
3. 最后再决定是改包、改 overlay 还是改脚本

## 实际应用

以下几个命令思路很常见：

- 重编单个包：`make <pkg>-rebuild`
- 重跑配置：`make <pkg>-reconfigure`
- 清理包目录：`make <pkg>-dirclean`
- 导出最小配置：`make savedefconfig`

## 光猫中的体现

在光猫项目里，最容易踩坑的是：

- 把厂商封装问题误认为 Buildroot 问题
- 把只读 rootfs 的限制误认为普通 Linux 异常
- 把私有驱动 ABI 问题误认为通用工具链问题

## 注意事项

- Buildroot 解决的是“系统构建”，不是所有产品问题。
- 对厂商 SDK，很多异常来自 BSP 或私有脚本，而不是 Buildroot 主树。
- 先把边界分清，再做排错。
