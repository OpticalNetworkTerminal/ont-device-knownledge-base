# 术语解释

## 简介

本文整理 EmbeddedRuntime 目录中最常见的术语，帮助读者建立稳定词汇表。

## 背景

嵌入式 Linux 文档最容易混乱的地方，就是同一个词在不同人嘴里指不同层次。例如：

- Rootfs
- sysroot
- SDK
- toolchain
- libc

## 基本概念

术语表的价值不在于“背定义”，而在于后续看 Buildroot / OpenWrt / GPL 代码包时能快速定位层次。

## 工作原理

本表按运行环境链路组织，从 CPU 到 Rootfs 再到开发环境。

## 设计目的

- 统一语言
- 减少误解
- 为后续章节提供稳定引用

## 优缺点

优点：

- 便于建立完整知识图谱

缺点：

- 定义偏抽象，必须结合其他章节理解

## 典型应用

- 读 GPL 代码包
- 分析 Rootfs
- 判断一个程序为什么不能运行

## 在 Buildroot 中的位置

Buildroot 文档、配置和目录布局几乎会用到本表中的大部分术语。

## 在 OpenWrt 中的位置

OpenWrt 虽然工程组织不同，但底层术语体系基本相通。

## 在光猫中的体现

光猫分析里最常见的概念混淆往往就是：

- 把 sysroot 当 Rootfs
- 把 SDK 当完整源码
- 把 libc 当“普通共享库”

## 实际案例

“把 SDK 里的库拷到设备上为什么没用”这个问题，通常只要把 `SDK / sysroot / Rootfs` 三个词分清，答案就清楚了。

## 实践操作

```bash
file busybox
readelf -l busybox
gcc -print-sysroot
```

结合这些命令，把“ELF / 动态链接器 / sysroot”三个概念对应起来看。
